1. What this app is

The Org62 Command Center is a small web app that runs on your own machine and gives you a single dashboard over your own Org62 opportunities — pipeline, forecast, ANZ Field Service white space, coaching signals, and how your time is spent. It is built for a Solution Engineer's view: it centres on the deals you're tagged on as a contributor, not deals you own.

Safe by design. It is read-only — it only ever runs SELECT queries and never writes back to Salesforce. It binds to 127.0.0.1 (your machine only, not reachable by anyone else), and it stores no passwords: it reuses the login token from the Salesforce CLI.

3. First-time setup & running it

The app ships with a one-shot script, run.sh, that does everything: builds its Python environment the first time, prompts you to log in to Org62 if needed, then starts the server.

1

Open the app folder in Terminal

If you already have the folder, just cd into it. If you're getting it fresh:

git clone https://github.com/ron-au25/FieldServiceCommandCenter.git
cd FieldServiceCommandCenter
2

Run it

./run.sh

First run takes a moment while it builds its environment. On later runs it starts almost instantly.

3

Open the dashboard

When you see Starting Org62 Command Center on http://127.0.0.1:5057, open that address in your browser:

http://127.0.0.1:5057

Leave the Terminal window running while you use the dashboard. Press Ctrl+C to stop it.

Different port? If port 5057 is busy, start it on another one: PORT=5099 ./run.sh then open http://127.0.0.1:5099. (On macOS, port 5000 is taken by AirPlay — that's why the default is 5057.)

4. Connecting to Org62 (login)

The very first time, run.sh notices there's no Org62 session and opens your browser to log in automatically. Complete your normal Org62 SSO. That's it — the CLI stores an encrypted token and the app reuses it.

To log in (or re-login after a session expires) manually:

sf org login web --alias org62

Confirm it worked:

sf org display --target-org org62

The Org Id should start with 00D000000000062 — that's Org62.

If login is blocked — requesting the permission set

If login fails with OAUTH_APP_ACCESS_DENIED or OAUTH_AUTHORIZATION_BLOCKED, your Org62 user isn't yet authorized for the Salesforce CLI connected app. You need this permission set:

Salesforce CLI (OOTB) Connected App Access
Salesforce_CLI_OOTB_Connected_App_Access · Id 0PSed000000jM2nGAE
This is not a self-service toggle, and not something a local admin simply grants. It's gated behind a TechForce intake request, and the perm set is assigned to your user only after that request is reviewed and approved.

How to request it

1

Open the intake form

Find “Salesforce CLI Connected App — Org62 Access Intake Request” on BaseCamp (search for techforce-salesforce-cli-connected-app-org62-access-intake-request). Or ask Slackbot: “I want to build an app to connect to org62 — I need this perm set in my org62. How can I get it?” and it will link the form directly.

5. Navigating the dashboard

Across the top is a KPI band (headline numbers), and below it five tabs. A status badge in the header tells you where the data came from: live = queried Org62 just now; snapshot = showing a bundled fallback because the live connection wasn't available. The ↻ Refresh button re-syncs with Org62 at any time.

The alert bar

A thin strip above the KPI band shows your 10 latest deal alerts — stage changes, amount changes, new comments, a deal going dead (✕), a deal closing won (🏆), or a new opportunity (✨) created under an account you're already working. Each chip is compressed to two lines (account name, then the alert with an icon/arrow); hover a chip for the full before/after detail plus the exact date and time, and click a chip to open that opportunity's detail drawer and jump straight to its highlighted row in the Open Pipe table below. Toggle it on/off in Settings (⚙).

The alert bar refreshes itself in the background — it doesn't wait for you to hit Refresh. Next to the live badge, a small clock shows when it last checked Org62; a subtle pulsing dot lights up next to it the moment a real change is found. If you switch away from the tab, an unseen alert also shows as a small red dot on the browser tab's favicon and a “•” prefix on the tab title — both clear as soon as you come back. How often it checks is configurable in Settings (default every 30 minutes) — see section 6.

The KPI band

Six cards at a glance: Closed Won (this fiscal year), Open Pipeline, Pipeline at Risk (stale / no next step / past close date), New Business (ANZ white space, with how many are aligned to your SEs), Time Spent this quarter, and a Dead/Excluded count. Click Closed Won, Open Pipeline, New Business, or Time Spent to jump straight to that card's tab. Click Pipeline at Risk to highlight the flagged rows in the Open Pipe table and show a panel underneath explaining exactly which rule flagged each one, with live counts; click it again to hide both.

The five tabs

TabWhat it shows
Open Pipe Your open opportunities, with a forecast-mix bar (Commit / Best Case / Pipeline). Columns include stage, Core SE, Service AE, close date, amount, and last activity (stale deals are flagged ⚠). This is your day-to-day “current opportunities” view.
Closed Pipe Deals that have closed. Shows Closed Won total; a “Show dead” toggle reveals lost/dead deals.
New Business (ANZ White Space) ANZ opportunities with in-scope product where you're not yet tagged — i.e. new opportunities to pursue. Rows aligned to your Service AEs are highlighted; a “Show only aligned” toggle filters to those.
Forecasting Coach Open deals that need attention, ranked by number of signals: past close date, stale (90+ days no activity), no next step, or no amount.
Activity Log Where your time goes: this-quarter hours vs. your target, a by-quarter breakdown (Customer Facing / Customer Related / Non-customer), dead-deal activity alerts, coverage gaps (business deals in your accounts you're not on), time-by-account for the last 14 days, and a month-by-month activity calendar — hover a day's activity chip for a full time breakdown.
Handy interactions on every table: click a column header to sort, type in the filter box to narrow by name / account / owner / stage, and click any row to open a detail drawer with SE & AE notes, activity, and product line items. Opportunity names link straight to the record in Org62.

6. Settings (⚙)

The gear icon (top right) opens a small panel. Your choices are saved on your machine and persist across restarts. The app version is shown at the bottom of the panel.

  • Role mode — FSL (Field Service) or Service Cloud. Switches which product scope and contribution role the white-space and activity views use.
  • Quarterly targets (hrs) — your Customer Related and Customer Facing hour goals, used by the target bars on the Activity Log.
  • Aligned SEs — a comma-separated list of the Service AE names you're aligned to. Drives the “aligned” highlighting/filtering on the New Business tab and the KPI card.
  • Show alert bar — toggles the deal-alerts strip above the KPI band (see “The alert bar” in section 5) on or off.
  • Check every N min — how often the app polls Org62 in the background for new alerts (1–240 minutes, default 30). Takes effect within about a minute of changing it — no restart needed.
Aligned-SE names must match exactly (case doesn't matter, but a nickname or typo won't match). If your “aligned” count looks suspiciously low or zero, check the spelling against the Service AE names shown in the table rather than assuming there's no data.

7. Where the data comes from

Every view runs a live SOQL query against your Org62 session when the page loads or you hit Refresh. If a live query can't run (no login, expired token), the app falls back to a bundled snapshot only if one exists on your machine — and the badge switches to snapshot. Snapshots are confidential and are not shared, so without a live connection the views will simply be empty and flagged. To go from empty to populated: log in (section 4), confirm sf org display works, and reload the page.

8. Troubleshooting

SymptomFix
Views empty, badge says snapshot with an error Login is missing or expired. Run sf org login web --alias org62, verify with sf org display --target-org org62, then reload.
OAUTH_APP_ACCESS_DENIED / OAUTH_AUTHORIZATION_BLOCKED on login You don't have the connected-app perm set. It's granted via a TechForce intake request, not a local admin — see section 4 → “If login is blocked” for the form and the four answers to submit.
Won't start / port error on 5000 Use another port: PORT=5057 ./run.sh (macOS AirPlay owns 5000).
ModuleNotFoundError when running manually Activate the environment and install deps: source .venv/bin/activate then pip install -r requirements.txt. (Or just use ./run.sh, which handles this.)
Wrong org's data Confirm the alias: sf org display --target-org org62 — Org Id must start 00D000000000062.
Copied the folder and it won't run No action needed — run.sh detects a stale environment and rebuilds it automatically.
